# DOC VAULT — منصة ملفات ومحاضرات الدكتور

مشروع Django جاهز كبداية عملية لمنصة مكتبة جامعية أونلاين. يدعم حساب دكتور، رفع الملفات، تصنيفها حسب المادة، وأكواد دخول مؤقتة للطلاب.

## المميزات الموجودة
- بوابة دكتور محمية بتسجيل دخول Django.
- لوحة تحكم وإحصائيات أساسية.
- رفع ملفات PDF والكتب والمحاضرات وتصنيفها حسب المادة.
- إدارة الملفات والمواد والأكواد من لوحة الإدارة.
- الطالب يدخل بكود يصدره الدكتور فقط.
- مدة صلاحية لكل كود، وحد اختياري لعدد مرات الاستخدام.
- الكود قد يفتح المكتبة كلها أو مادة واحدة فقط.
- منع التحميل لكل ملف على حدة.
- تخزين الكود مشفرًا (hash) وعدم حفظه كنص صريح.
- الملفات تمر عبر تحقق الصلاحيات قبل العرض/التحميل.
- SQLite للتجربة، PostgreSQL للنشر، وتخزين S3 خاص اختياري للإنتاج.

## التشغيل المحلي الأسهل (Docker)
1. انسخ `.env.example` إلى ملف باسم `.env`.
2. غيّر `SECRET_KEY` وكلمة مرور الدكتور في `docker-compose.yml` أو متغيرات البيئة.
3. شغّل:
   ```bash
   docker compose up --build
   ```
4. افتح `http://localhost:8000/`.
5. دخول الدكتور: `http://localhost:8000/doctor/login/`.
   بيانات Docker الافتراضية:
   - username: `doctor`
   - password: `ChangeThisNow123!`
   غيّرها فورًا قبل استخدام أي بيانات حقيقية.

إذا لم يُنشأ المستخدم تلقائيًا، نفّذ:
```bash
docker compose exec web python manage.py createsuperuser
```

## تشغيل بدون Docker
```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```
افتح `http://127.0.0.1:8000/`.

## استخدام الدكتور
1. سجّل الدخول من `/doctor/login/`.
2. أضف المواد أولًا من `/doctor/admin/library/subject/`.
3. ارفع الملفات من `/doctor/upload/` أو من لوحة الإدارة.
4. أنشئ كودًا من `/doctor/codes/` وحدد مدة الصلاحية وعدد الاستخدامات والمادة (اختياري).
5. انسخ الكود فور ظهوره وابعته للطالب. لا يمكن استرجاع الكود كاملًا بعد إغلاق شاشة الإنشاء؛ يمكن إنشاء كود بديل.

## إعداد التخزين السحابي للملفات
للإنتاج مع مئات الملفات، استخدم Bucket خاصًا متوافقًا مع S3 (مثل AWS S3 أو Cloudflare R2 أو مزود S3 آخر):
- أنشئ Bucket خاصًا وليس Public.
- اضبط `USE_S3=True` ومفاتيح التخزين في متغيرات البيئة.
- لا تضع مفاتيح التخزين في Git أو في الواجهة.
- فعّل HTTPS على الدومين.
- اضبط سياسة CORS حسب الدومين عند الحاجة.
- اختبر رفع وقراءة الملفات الكبيرة قبل إطلاق الموقع.

## النشر
المشروع يحتوي Dockerfile، ويمكن نشره على منصة تستضيف تطبيقات Django/Docker مع PostgreSQL وPersistent/Object Storage. لا تضع ملفات الطلاب في قرص مؤقت خاص بوظائف serverless. اربط التخزين السحابي الخاص قبل الاستخدام الفعلي.

## ملاحظات أمان مهمة قبل إطلاقه للطلاب
- غيّر كلمة مرور الدكتور الافتراضية و`SECRET_KEY`.
- اجعل `DEBUG=False` و`ALLOWED_HOSTS` للدومين الفعلي.
- استخدم HTTPS وPostgreSQL وBucket خاص.
- أضف نسخًا احتياطيًا لقاعدة البيانات والملفات.
- يفضل إضافة Rate limiting لمحاولات إدخال الأكواد، ومراجعة سجلات الدخول.
- منع التحميل لا يمنع تصوير الشاشة أو نسخ المحتوى الذي يظهر للمستخدم.
- عداد الاستخدام الحالي يحسب مرات تفعيل الكود، وليس كل صفحة أو كل تحميل.

## ملفات المشروع
- `config/`: إعدادات Django والروابط.
- `library/`: النماذج، الصلاحيات، الرفع، الأكواد.
- `templates/`: واجهات الدكتور والطلاب.
- `static/`: تنسيق الموقع.
